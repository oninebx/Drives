## Objective

Build an independent, loosely coupled Authentication module to separate authentication concerns from the application's core functionalities, and implement the Auth0 OIDC authentication strategy within this module.

This task will replace the existing OIDC implementation with the new strategy-based approach, establishing a consistent authentication interface for application components while keeping Auth0-specific implementation details encapsulated within the OIDC strategy.

## Objective

Establish a loosely coupled Authentication module and replace the existing Auth0 OIDC implementation with a strategy-based approach, separating authentication concerns from core application functionalities.

## Scope

1. Define a common set of authentication strategy methods and establish how strategies are selected, managed and consumed by the application.

2. Integrate Auth0 using the strategy abstraction and remove existing dependencies between the Auth0 implementation and core application functionalities.

3. Implement the OIDC strategy using the new abstraction and replace the existing OIDC implementation.

4. Decouple the OIDC strategy from Brand-specific implementations, allowing new Brands to be supported through extension, with TWR excluded from this scope.

5. Ensure that changes do not impact any existing Core Functionality.

6. Remove obsolete Auth0 OIDC-related code following the refactoring.

## Acceptance Criteria

- The new Authentication module and strategy abstraction are in place.
- Auth0 OIDC is fully integrated through the new OIDC strategy.
- OIDC implementation is decoupled from Core Functionalities and Brand-specific implementations (excluding TWR).
- Existing OIDC authentication flows and all Core Functionalities continue to work as expected.
- Obsolete Auth0 OIDC implementation code is removed.

### 3. Application Integration

- Integrate the new Authentication module into the existing application.
- Migrate existing authentication consumers to the common interface.
- Ensure existing post-authentication processes, including user matching and customer loading, continue to work as expected.
- Remove obsolete OIDC implementation code and unnecessary Auth0 dependencies from application-level components.

### 4. Testing and Validation

- Add or update automated tests covering the Authentication module and OIDC strategy.
- Validate login, callback, authentication state transitions, token handling and logout.
- Verify that existing application flows remain functional after replacing the OIDC implementation.
- Ensure authentication errors and loading states are handled correctly.

## Acceptance Criteria

- An independent Authentication module is established with clearly defined responsibilities.
- Authentication functionality is exposed through a common interface.
- Auth0 OIDC is implemented as an independent authentication strategy.
- Auth0-specific implementation details are isolated from core application functionality.
- The existing OIDC implementation is replaced by the new strategy.
- Existing post-authentication processes and application functionality continue to work as expected.
- Automated tests cover the key authentication scenarios.
- No regression is introduced to the existing OIDC authentication flow.

## Out of Scope

- Implementation of the Legacy authentication strategy.
- Changes to the existing Legacy authentication flow.
- Authorization and permission management beyond the existing OIDC requirements.





## Objective

Implement the Auth0 Legacy authentication strategy using the Authentication module and strategy abstraction established in the previous ticket.

The objective is to support the existing username and password authentication flow through the new strategy-based architecture, while maintaining separation from OIDC-specific implementation and Core Functionalities.

## Scope

1. Implement the Legacy authentication strategy using the existing authentication strategy abstraction.

2. Integrate the existing Auth0 Legacy (username/password) authentication flow into the new strategy.

3. Ensure the Legacy strategy remains independent of the OIDC strategy and its implementation details.

4. Ensure the Legacy strategy can be selected and used as an alternative to the OIDC strategy, with only one authentication strategy active at a time.

5. Preserve the existing Legacy authentication behaviour and ensure no impact on Core Functionalities.

6. Remove obsolete Legacy authentication code following the migration.

## Acceptance Criteria

- Auth0 Legacy authentication is implemented through the new strategy abstraction.
- Username and password authentication works as expected.
- Legacy and OIDC strategies remain independent and mutually exclusive.
- Existing Legacy authentication flows and all Core Functionalities continue to work as expected.
- Obsolete Legacy authentication implementation code is removed.
